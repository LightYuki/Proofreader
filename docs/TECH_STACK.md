# 技术选型与最小架构

应用版本：1.0.0（固定，未经用户要求不递增）  
日期：2026-09-23  
关联需求：[产品需求与交互规格](./PRODUCT_SPEC.md)

## 1. 开发基线

第一版选择 **Tauri 2 + React + TypeScript + Vite**，以少量 Rust 代码提供本机能力，优先交付 Windows 桌面安装版。

选型优先考虑小工具的分发体积、界面迭代和实现简洁。用户本机已有 Rust 环境，明确倾向 Tauri。主要界面与业务仍使用 TypeScript，无须将全部校润逻辑改写为 Rust。

| 部分 | 选择 | 负责内容 |
| --- | --- | --- |
| 主要业务语言 | TypeScript | 类型、窗口计算、批次调度、结果归并、审阅状态 |
| 原生语言 | Rust | 本地文件、配置保存、异步 HTTP、必要的系统能力 |
| 桌面框架 | Tauri 2 | 窗口、菜单、命令通信和桌面打包 |
| 界面框架 | React | 连续双语正文、审阅面板、问题导航和弹窗 |
| 页面样式 | HTML + CSS Modules + CSS 变量 | 双栏布局、差异标记、集中管理颜色、字体和尺寸 |
| 界面构建 | Vite | 前端开发服务和生产资源构建 |
| 状态管理 | React 内置状态机制 | 当前条目、审阅草稿、弹窗及视图状态 |
| 本地数据 | JSON 文件 | 普通配置、工作记录及译文输入输出；不引入数据库 |
| 打包 | Tauri CLI／bundler | 第一版使用 Windows NSIS 安装包（setup.exe） |

React 界面运行于 WebView。Vite 和 Node.js 用于开发与构建，发行版加载打包后的本地静态资源，不附带 Node.js 服务。Rust 随应用编译，用户无需安装 Rust 或前端开发工具。

发行版不引入 Python、本地 HTTP 服务器、sidecar 进程或大型编辑器框架。React 工作台现已接入真实文件和模型命令；`fixtures/` 中的本机 HTTP 服务仅供开发联调。

工程现已初始化，依赖版本写入 `package-lock.json` 及 `src-tauri/Cargo.lock`。前端采用 React 19、TypeScript 7、Vite 8 和 Vitest 5；桌面使用 Tauri 2，Rust HTTP 层使用 reqwest 0.12。

## 2. 选择理由与体积取舍

| 方案 | 对本项目的评价 |
| --- | --- |
| Tauri 2 + React + TypeScript | 保留 Web 界面的灵活性，Windows 复用 WebView2；已有 Rust 环境，适合作为当前基线 |
| Electron + React + TypeScript | 业务语言集中，但随应用分发 Chromium 和 Node.js，与用户希望安装包较小的要求不符 |
| Python + PySide6 | 文件和网络逻辑直接，但当前双语长文本与差异审阅需要更多控件定制，分发也需处理 Python 与 Qt 依赖 |

Tauri 有额外的原生构建工具链和前后端通信边界，但本项目只需少量固定命令，能够限制这部分复杂度。

Windows 使用共享 WebView2 Runtime：已安装时复用，缺失时由安装程序引导下载和安装。默认不捆绑完整的固定版本 WebView2，也不附带完整离线 Runtime 安装程序。

如果以后要求“无网络且目标机器没有 WebView2 也能安装”，需要单独考虑离线分发包，其体积会明显增加。安装包、安装后磁盘占用和实际内存使用是不同指标，具体数值以构建与运行测量为准，不预先承诺固定大小。

## 3. 最小职责划分

```text
React + TypeScript（WebView）
  连续正文、审阅状态、60／30 窗口与批次流程
             │
             │ 少量类型化的 invoke 命令
             ▼
Tauri + Rust（本机能力）
  文件、配置、异步模型请求、取消请求
             │
             ▼
本地 JSON 文件 + 用户配置的 LLM 服务
```

### 3.1 TypeScript 业务与界面

- React 实现左右双语正文与右侧建议；文件标签、最近记录、菜单与独立弹窗承载文件切换、导入、校润要求和设置。
- 管理当前条目、编辑草稿、审阅决定和问题导航，以及各文件的可恢复工作快照。
- 将 60／30 窗口计算、检查区判断和建议归并写成独立纯函数。
- 顺序调度批次，管理进度、停止、失败重试和任务标识。
- 通过 Rust 命令发起当前批次请求，异步等待期间保持界面可用。
- 保存时向 Rust 提交已确认的条目索引与替换文本。

`App.tsx` 负责工作台组装、顶层弹窗和快捷键；文件标签、最近记录、模型选择、各类弹窗及审阅区域分别实现。`useWorkbench` 集中管理检查、审阅和文件切换流程，`core/review.ts` 保留不依赖 React 的审阅算法，`features/workspace/state.ts` 处理工作记录的捕获、恢复、文件身份和写入排序。业务流程不复制到 Rust；第一版使用 React 内置状态机制，是否增加虚拟列表，由实际长文件的性能验证决定。

### 3.2 Rust 本机能力

- 使用原生文件对话框选取输入和输出位置，读取并解析原文及译文。
- 保留完整的原始译文数据；只向界面提供需要显示、审阅的字段。
- 保存时在原始译文上应用已确认修改，保留其他字段和数组顺序。
- 负责普通配置、工作记录的原子写入和 API Key 的本机管理，读取配置时不把已保存密钥返回给界面。
- 负责异步 HTTP、模型列表、连接测试、请求取消和必要的错误信息。
- 文件和网络能力封装为明确命令，不提供执行任意代码或任意网络代理的通用入口。

Rust 端使用 serde／serde_json 处理结构化数据，启用字段顺序和任意精度数字保留；reqwest＋rustls 处理 HTTP，Tauri 官方对话框插件处理文件选择及确认，keyring 对接 Windows 凭据管理器。只启用所需能力。

这里的“薄层”指不重复业务流程；保存索引范围、请求参数和文件操作等必要边界检查仍由 Rust 执行。

### 3.3 通信边界

前端通过一个小的 TypeScript 模块集中调用 Tauri `invoke`，组件不直接分散拼装命令参数。

命令能力控制在打开文件对、读取／保存设置和工作记录、获取模型、测试连接、请求一个批次、取消请求和保存校润版等范围。请求与响应使用 JSON 可序列化的数据，字段结构在前后端保持一致。

## 4. 批次与模型请求

- 固定前 15 条＋检查 30 条＋后 15 条，推进 30 条，首尾自然截断。
- `shared/review-policy.json` 是窗口参数的统一来源：前端经 `src/config/review.ts` 使用，Rust 经 `src-tauri/src/policy.rs` 嵌入读取；界面提示、窗口生成和请求边界保持一致。参数仍是固定产品规则，不增加高级配置界面。
- TypeScript 顺序调度，一次只请求一个批次；Rust 不再维护第二套批次队列。
- Rust 异步请求用户配置的模型服务，避免 WebView 直接请求不同服务商时受到浏览器跨域规则影响。
- 首版按完整批次响应处理建议，不做逐 token 流式展示。
- 使用 OpenAI 兼容的 `/chat/completions` 接口，发送 `model`、`messages`、`stream: false`，读取 `choices[0].message.content`。Base URL 可为基础地址或完整端点。
- 模型发现使用同一接口根路径的 `GET /models`，读取 `data[].id`，去除空项并排序去重；无需已有模型名称，列表不可用时保留手填入口。服务地址或密钥变更使旧列表和未完成响应失效。
- 每个任务和请求带标识；停止或重新开始后，旧请求的迟到结果不应用到新任务。
- 停止时不再派发后续批次，并取消当前请求；不能及时取消时也必须忽略旧结果。
- 用户手动重试失败批次，不自动重试；以原始条目索引归并，不重复添加建议，不覆盖用户已确认、已保留原译或手动编辑的审阅项。
- 重新检查仍以导入时的原译文为输入，每次开始时记录校润要求快照。
- `prompts/review.md` 独立维护系统规则，`prompts.rs` 定义风格／背景字段并组装消息；`llm.rs` 负责范围检查、HTTP 和响应提取。语言方向由用户写在风格要求中，无语言枚举和允许值列表；未明确指定时沿用现有译文语言，理由与依据使用中文。
- 连接超时 20 秒，请求超时 120 秒；不跟随 HTTP 重定向，服务错误中的当前 API Key 会被遮盖。

无需为了这些网络操作建立本地服务器、线程池或独立任务服务。

## 5. 文件与状态存储

- 用户输入和校润输出都是 JSON 文件。
- 校润版只写译文数据，不混入模型建议、批次或审阅状态。
- Base URL、模型名存于 Tauri 应用配置目录 `com.proofread.desktop`；风格和背景的默认偏好使用 WebView 的 localStorage 保存，各文件使用独立要求快照。
- API Key 为选填，存于 Windows 凭据管理器，不写入前端 localStorage、工作记录、日志或校润版文件；前端仅获知是否已有密钥，并提供占位提示及“清除”操作。输入省略表示同源时沿用，显式空字符串表示清除，跨源地址不复用旧密钥。
- 获取模型和测试连接不修改旧凭据；保存时应用替换或移除，配置写入失败时恢复原凭据。旧配置的禁用标记仅用于迁移读取，不再对外返回或保存，旧版禁用的密钥不会被重新启用。
- `readRequirements` 共用于默认偏好和工作记录解析，保留风格／背景文本并去掉旧语言字段；保留原存储键及工作记录格式版本 1，避免升级清空进度。应用发布版本固定为 1.0.0，不与记录格式版本联动。
- `workspace.json` 由 Rust `workspace` 模块读写，带格式版本，包含打开标签、当前文件、最近记录和各文件的路径、输入内容标识、建议、草稿、人工决定、批次、要求、当前行、输出路径与保存状态，不包含密钥。正常编辑延迟自动保存，写入队列按调用顺序串行执行，防止旧快照覆盖新进度。
- 切换文件、关闭标签或退出程序先停止相关检查并写入快照。重新打开相同文件对时恢复进度；正在运行的批次恢复为待处理，撤销历史不持久化。输入文件内容标识变化时重置过期审阅结果及输出路径并提示，保留该文件的校润要求。
- 损坏或不受支持的工作记录提示读取失败并保留原文件；原子写入失败不静默丢弃进度。关闭标签保留记录；最近列表隐藏使用会话的可选 `hiddenFromRecents` 字段，旧记录默认可见，格式版本仍为 1。隐藏不删除会话，重新打开文件对时恢复可见。隐藏失败只回退该记录的可见性，不回退其他文件或后台批次的新进度；文件操作期间暂停延迟自动保存，结束后保存最新快照。原 JSON 不受影响。
- 保存从原始译文应用已确认修改，保留未修改字段与条目，通过同目录临时文件写入后替换。禁止覆盖导入的原文或译文。

## 6. 最小代码组织

```text
src/
  App.tsx               工作台组装、顶层弹窗和快捷键
  App.module.css        工作台与组件样式
  main.tsx              前端入口
  components/           文件标签、最近记录、模型选择、菜单和弹窗
    PopupMenu.tsx       文件与右键菜单共用的焦点、边界和弹窗内浮层
    WorkbenchContextMenu.tsx  按位置解析右键目标，执行前重新核对工作台状态
    menuEvents.ts      文件菜单、右键菜单与模型列表之间的互斥打开及焦点回退
  config/review.ts      窗口策略入口、要求默认值与兼容读取、撤销上限
  features/review/      审阅流程及状态
    components/         正文、问题导航、审阅面板和显示辅助函数
  features/workspace/   工作记录、会话恢复、文件身份及持久化顺序
  core/                 窗口计算、建议归并、撤销决定与测试
  services/             Tauri 命令的 TypeScript 封装
  styles/tokens.css     颜色、字体、面板尺寸等 CSS 变量
  types.ts              前端数据与命令类型
src-tauri/
  src/                  Rust 命令、文件、模型、配置、工作记录和共享策略
    prompts.rs          校润要求类型和消息组装
    prompts/review.md   与语言组合无关的系统提示词
  capabilities/         必要的 Tauri 能力配置
  tauri.conf.json        应用及打包配置
shared/review-policy.json  前后端共用的 30／15／15 窗口策略
fixtures/                样例 JSON 与本机模拟模型服务
```

优先验证窗口与拼接的实际风险：空文件、30 条边界、最后不足 30 条、建议返回乱序或越界、失败重试不重复、旧请求结果不覆盖新任务，以及写回保留未修改条目和字段。

Vitest 仅发现 `src/**/*.test.{ts,tsx}`，将应用测试与本地安装技能工具自带的 Node 测试分开。

界面静态渲染用于检查标签、草稿显示与状态表达；CSS 检查用于核对中性色和对比度。静态检查不等于实际窗口布局验收。分别验证 TypeScript 纯逻辑与 Rust 写回边界，不为同一业务规则维护两套实现。本轮按用户要求不补测试，实际执行范围见下文。

## 7. 开发环境与交付

- 已确认本机 Rust、Cargo、Node.js 和 npm 命令可用。
- 已检测到 Microsoft C++ Build Tools／Windows SDK 与 WebView2，前端生产构建和 Rust 调试构建已通过。
- 第一版优先 Windows 安装版，其他平台暂不承诺。
- 默认使用 Tauri 的 NSIS 打包及 WebView2 引导安装方式；不为小工具默认附带整套浏览器运行时。
- Windows 最低支持版本在选定依赖版本及打包验证时确认。
- 安装程序签名、自动更新及额外离线安装包不作为首版核心功能。

工程和依赖初始化已完成。2026-09-24 第二轮优化后，现有 70 项 Vitest、34 项 Rust 测试、前端生产构建及 Windows release 构建通过，未新增或改写测试。现有测试覆盖可选密钥、模型列表、旧记录兼容、语言指导传递、输入变化及原子写入。真实模型服务尚未测试；模拟 IPC 浏览器预览不替代完整桌面验收。

本轮增加 Windows 专用 `windows-sys` 直接依赖，用于系统互斥锁、窗口恢复与激活；未升级其他依赖版本。新增 `reset_settings`／`validate_settings` 命令和可选工作记录字段 `manualEdited`、`roundId`、`round`；工作记录版本仍为 1。轮次记录要求快照、模型、服务来源及连接摘要，不保存密钥或完整 URL 查询参数。没有引入搜索库、状态库或数据库。

本轮重新生成独立 EXE，文件版本仍为 1.0.0，并记录 SHA-256；目录整理后转存到本机 `release/proofread.exe`，旧 ZIP 与编译缓存已清理。Git 只记录源码及必要项目文件，首次重新构建需要重编 Rust 依赖。构建信息及验收边界见 [优化实施记录](./OPTIMIZATION_REVIEW.md#本轮验证与交付)。

之前的 NSIS 工具下载受连接失败影响，标准安装包配置保留，当前使用独立 EXE。历史便携 ZIP 已清理。开发、测试和打包命令见 [README](../README.md)，当前架构评估见 [ARCHITECTURE_REVIEW.md](./ARCHITECTURE_REVIEW.md)。

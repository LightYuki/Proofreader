## 复核判断与具体实现

### 1. 样式与菜单

第一轮只对部分轻量按钮添加例外，仍留下全局圆角、全局 hover 灰底，以及输入框的偏移外圈。本轮调整基础规则，再分别定义文字、图标、实体按钮、输入框、菜单与列表反馈。

- `tokens.css` 分开控件半径 0px 与浮层半径 2px，减弱浮层投影；状态灯与保存圆点保持圆形。
- `App.module.css` 移除普通按钮的全局 hover 填色；主要深色按钮保留明暗反馈。文字操作以颜色反馈，菜单／列表使用直角整行高亮，选中状态不被 hover 覆盖。
- 所有文本输入的 hover 不增加样式；focus 只改变原 1px 边框颜色，无外圈、阴影、尺寸变化。键盘操作仍有内部细线、下划线或活动行提示。
- 保留输入框系统右键菜单、菜单目标复核、Esc、键盘定位和焦点返回。弹窗在显示后聚焦可编辑字段。

没有引入 CSS 框架、动画或装饰卡片，没有更改现有栏宽、字体和字号。

### 2. 人工成果保护

旧逻辑仅用 `draft === proposed` 推断建议未被编辑，无法保护“人工编辑后又改回模型原措辞”的情况。

本轮给 `ReviewItem` 增加可选 `manualEdited`。新模型条目在接收结果时明确标为 `false`；实际编辑、保留原译、恢复待审均保留人工保护。合并只替换未处理且未编辑的模型建议，只有对应批次成功返回后才更新；失败不会先删旧建议。

保留原译后输入新文字会回到待审，自动参与待审计数和 F8 导航。已采用内容仍与未确认草稿分开，未再次采用前，正文和 JSON 使用上次确认的内容。撤销决定保留之后的输入。

旧记录缺少标记时，在激活会话时按已编辑处理；读取工作记录本身不改写其他旧条目。工作记录版本保持 1，新增字段可选，不能为了升级字段清空进度。

入口：`core/review.ts`、`useWorkbench.ts`、`types.ts`、`workspace/state.ts`。

### 3. 设置异常与检查前校验

设置区分加载中、可用和读取失败。失败不再禁用设置入口；弹窗显示原因、重试读取，以及“备份并重新填写”。重试保留已输入的表单内容；明确重建才用恢复后的配置替换表单。

Rust 将配置读取与凭据读取分开。地址和模型能读取时继续显示，密钥异常通过 `credentialError` 表达，不冒充没有密钥。表单允许重试或明确“不使用密钥”；凭据仍不可读时，更换密钥可能失败并保留旧配置，不盲目覆盖旧凭据。

重建先复制原配置到同目录 `settings.recovery-<UUID>.json`，备份失败则不替换。重建、配置文件缺失、旧版禁用密钥或跨服务无密钥保存时，都不自动复用归属未知的旧密钥。`disableSavedKey` 将此选择持久化；凭据暂不可读时可以留下旧凭据但永久禁止自动复用。密钥仍由 Windows 凭据管理器存储，不写入工作记录。

`validate_settings` 在创建或重置批次前检查地址、模型和凭据是否可读，不发送网络请求。校验失败不改变已有批次和轮次。JSON 保存与工作记录保存仍使用既有原子写入逻辑。

入口：`settings.rs`、`lib.rs`、`desktop.ts`、`SettingsDialog.tsx`、`useWorkbench.ts`。

### 4. 同一配置目录的单实例保护

原子保存只能防止半写文件，不能避免两个工作进程互相覆盖完整快照，因此需要单实例保护。

官方插件下载受到本机证书环境影响，本轮采用 Windows 系统互斥锁，并只增加 `windows-sys` 的直接依赖，其他依赖版本不变。锁名称由配置目录生成；锁由系统在进程结束时释放。`instance.pid` 只提供窗口激活线索，不能以文件是否存在判断锁状态。

第二次启动尝试恢复最小化窗口并激活它，随后退出。激活失败显示明确提示，也不允许第二个进程加载或保存工作记录。锁在管理共享应用状态之前取得；不引入数据库、后台服务或多窗口同步。

入口：`single_instance.rs`、`lib.rs`。实际 Windows 重复启动、最小化恢复及异常退出流程尚未人工验收。

### 5. 原要求继续与新要求重新检查

`CheckRound` 随会话保存轮次 ID、风格／背景快照、模型、服务来源及连接摘要；建议保存来源轮次 ID。进度不保存 API Key，也不复制完整 Base URL 的查询参数。连接摘要用于识别同一服务下路径或参数发生变化。

存在待继续或失败批次，且当前要求／连接与原轮不同，弹窗提供：

- **按原要求继续／重试失败批次**：使用原轮的要求快照，保留已完成部分和当前表单里的新要求。状态栏显示“沿用原要求”。
- **按当前要求重新检查**：对全文创建新轮次，保留人工草稿及决定，成功返回的批次才替换未经处理的旧建议。
- **取消**：保留现有状态并返回原入口。

模型连接改变时，两种选择都明确使用当前连接并记录新的来源。没有待继续内容时，主按钮直接重新检查，不提供无效的继续动作。旧记录没有要求快照时不伪造原要求，只允许开始新轮。保留的旧建议在审阅栏注明较早轮次或来源未记录。

入口：`RoundChoiceDialog.tsx`、`useWorkbench.ts`、`ReviewPanel.tsx`、工作记录类型与校验。

### 6. 保存、失败与空状态

进度持久化沿用防抖和串行写入，并增加递增修订号与写入序号。只有最新写入涵盖当前修改才显示“进度已保存”；旧回调不能把较新的修改标成已保存。隐藏、打开、关闭和自动保存共用状态通道。

JSON 状态独立显示。输出成功会说明已保存修改数及剩余待确认数；不会自动采用草稿，也不会抹去进度保存错误。

问题列表与审阅栏区分未开始、尚未完成、运行中、失败和完成无建议。有失败批次时不显示无条件的“全部已审阅”。当前行的批次错误可在原审阅区域展开查看。

入口：`useWorkbench.ts`、`App.tsx`、`IssueNavigation.tsx`、`ReviewPanel.tsx`。

### 7. 查找、跳转与文件辨识

Ctrl+F 查找当前文件的原文、正文正在显示的译文及说话人，采用普通文本匹配，不将输入作为正则。未确认草稿、理由和依据不混入结果。提供数量、上一／下一匹配、首尾循环提示；Enter／Shift+Enter 切换匹配，Esc 收起并返回原焦点。高亮使用灰阶，不改文本和审阅决定。

Ctrl+G 输入一基行号，校验 1 到总条目数。定位目标有独立请求序号，同一行的不同匹配也能滚动定位。切换文件清除旧查找目标；后台结果变化可以更新匹配，但不自动移动用户位置。

临时浮层放在正文现有标题区域上方，不新增工具栏、不改变列宽。正文右键提供同样的查找和行号命令。最小窗口 900×620 的浏览器预览中，展开问题列表时仍可完整使用定位浮层。

重名文件标签在原宽度内显示最短可区分目录；同一译文配对不同原文时显示原文区别。活动标签和问题项随主动选择滚入可见范围，后台更新不触发滚动。

入口：`ReaderNavigation.tsx`、`search.ts`、`BilingualReader.tsx`、`DocumentTabs.tsx`、`WorkbenchContextMenu.tsx`。

- 不开展真实模型质量评估或新增自动化测试，不引入全局状态库、搜索库或数据库。

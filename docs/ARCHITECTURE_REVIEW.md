日期：2026-09-23。范围：当前源码中的固定参数、模块职责、扩展入口，以及本轮界面整理的验证状态。

2026-09-24 第二轮更新：已实现 [优化复核后的确认范围](./OPTIMIZATION_REVIEW.md)，以及 [菜单与样式规则](./MENU_OPTIMIZATION_PLAN.md)。新增明确的人工编辑保护、轮次要求快照、设置恢复与启动前校验、带修订号的保存状态、查找／跳转和按配置目录保护的 Windows 单实例。单实例使用 `windows-sys`，未升级其他依赖；工作记录仍为版本 1，新增字段可选。未新增或修改测试，布局不变。当前 70 项 Vitest、34 项 Rust 测试与生产构建通过；以下早期扫描结果保留为历史，当前验证边界见实施记录。

当前结构适合多个文件对、单个活动文档串行检查、人工确认的小工具。界面展示、审阅算法与工作记录读写已分开，核心规则集中到有限几个入口，暂不需要额外状态库、插件系统或通用工作流框架。

### 硬编码复核

复核范围：前端与 Rust 生产代码、`shared/`、开发和打包配置；测试、样例、生成文件及 `.cache/` 单独区分。未发现把用户填写的 Base URL、模型、密钥或校润要求覆盖为固定值的代码，也未在检查的生产代码中发现真实 API Key、个人绝对路径或测试模型名称。

已移除语言硬编码，并将应用版本统一固定为 1.0.0。其余维护点按实际用途保留，不增加设置界面：

| 项目 | 位置 | 当前影响与建议 |
| --- | --- | --- |
| 原文／译文语言限制 | `src/config/review.ts`、`src-tauri/src/prompts.rs`、`src-tauri/src/prompts/review.md` | 已移除 EN／JP 选项与后端允许值检查，界面统一使用“原文／译文”。具体语言在风格要求中表达，未明确指定目标语言时保持现有译文语言；中文理由属于固定界面约定。 |
| 开发端口 1420 重复配置 | `package.json`；`vite.config.ts`；`src-tauri/tauri.conf.json` | 仅影响开发启动；CLI 参数还会覆盖 Vite 配置。可先移除 npm 脚本中的重复参数，后续统一 Vite 与 Tauri 的开发地址来源。发布版不依赖此端口。 |
| 少量未命名的数量上限 | `src/components/ModelPicker.tsx`（100 个匹配项）；`src/App.tsx`（5 条最近记录）；`src-tauri/src/llm.rs`（600 字符错误说明） | 属于显示限制，模型仍可搜索／手填，最近记录仍可查看全部。建议改为各模块的命名常量，不必增加用户设置或通用配置框架。 |
| 工作记录版本 1 多处声明 | `src/types.ts`；`src/features/workspace/state.ts`；`src-tauri/src/workspace.rs` | 当前一致。以后升级记录格式须同步前后端并设计迁移；版本号属于持久化格式约定，不应变成用户可随意修改的设置。 |
| 应用版本 1.0.0 | `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json` | 自身包版本已统一为 1.0.0，未经用户明确要求不递增；依赖版本不修改，工作记录格式版本仍为数字 1。 |

以下固定值合理保留：

- `shared/review-policy.json` 的 30／15／15 是已经约定的产品规则，前后端共用；测试里的 60／30 预期值用于独立验证该约定，不应为了去重而改成直接复制实现结果。
- 请求 120 秒、连接 20 秒、自动保存延迟 400ms、撤销上限 50 已有命名常量，且各自只有一个配置入口。较慢模型可能触及请求超时，确有需要时再开放超时设置。
- OpenAI 地址是首次启动默认值，可保存为任意受支持的 HTTP(S) 服务；模型名默认空，密钥来自用户输入和系统凭据管理器。
- `message`／`name`、`/chat/completions`、`/models`、`stream: false` 是目前明确支持的数据格式和接口方式。
- CSS 颜色均位于 `src/styles/tokens.css`；字体、基础圆角和面板宽度也已有统一入口。局部间距、字号、断点和 250ms 悬停延迟属于组件表现参数，无须全部转为运行时设置。
- 应用标识和凭据命名空间是稳定身份。变更它们应考虑已有设置和密钥的迁移，不能作为普通去重随意替换。

旧记录迁移只丢弃废弃的语言字段，保留风格、背景、审阅建议、采用文本、后续草稿、批次和阅读位置。应用标识、凭据命名空间及本地存储键保持不变。

| `features/workspace/state.ts` | 工作记录解析、捕获与恢复、文件身份比较、标签切换和串行写入。 |

| Rust `documents`／`settings`／`llm`／`prompts`／`policy`／`workspace` | 分别负责原始 JSON 与写回、配置与密钥、HTTP 及范围检查和模型列表、校润消息与独立系统提示词、共享窗口参数、工作记录原子写入与损坏备份；`lib.rs` 组装命令与应用状态。 |

`useWorkbench` 仍集中承担主要流程，当前只有一种工作台和一种批次执行方式，保留这一组织方式更便于追踪。只有出现第二种独立流程时再拆分调度器。展示组件共用工作台 CSS Module，当前可接受；样式明显独立增长时再按组件拆分。

## 后续扩展入口

- 使用不同语言组合：直接在风格要求中填写原文与译文语言，无须修改类型、允许值或下拉控件。模型自身的语言能力仍需用实际文件评估。
- 调整校润规则：修改 `prompts/review.md`；只有请求字段或返回结构变化时才修改组装／解析代码。
- 接入不同模型协议：在 Rust 模型模块增加明确的请求／响应适配，保持前端建议结构不变。当前的自定义 Base URL 不等于支持任意协议。
- 工作记录扩展：`workspace.json` 已独立保存文件身份、建议、草稿和进度；新增字段时同步更新类型、解析与恢复。输出译文 JSON 仍只含原数据及已确认修改。当前按单窗口使用，多进程间没有协调写入。
- 处理更长文件：先测正文渲染与内存，再决定是否为 `BilingualReader` 加虚拟列表；当前仍完整保留原始译文，以保证写回字段不丢失。
- 增加场景边界：应显式记录用户分段，再限制窗口覆盖范围；不要通过说话人变化猜测场景。

这些都是按实际需求增加的入口，不列为当前待完成的第一版功能。

## 验证状态

70 项 Vitest 测试、34 项 Rust 测试及前端生产构建通过。测试覆盖窗口边界、人工草稿与撤销、JSON 保留、模拟 HTTP、取消、可选密钥、模型列表、工作记录与损坏备份。本轮增加旧 EN／JP 记录兼容、无语言选择字段、任意语言要求传递与无语言要求的用例。测试验证数据传递和边界，不代表真实模型会始终正确遵循语言要求。

组件静态渲染确认统一“原文／译文”标签、校润要求无语言选择器、待确认草稿与问题数量一致、正文保留已采用译文。CSS 变量引用与纯中性色检查通过，已检查文字对比度至少 4.5:1，四种实色状态灯对白底至少 3:1。

`kill-ai-slop` 扫描 28 个前端文件，2 组、5 处匹配均有实际功能：键盘焦点下划线、真实修改对照及其新增下划线、未保存圆点和用户选择的静态审阅灯，保留理由见 `UI_REVIEW.md`。

本轮遵照用户要求不使用 Computer Use，未打开应用或访问真实模型服务。1.0.0 发布程序已通过离线 Tauri 构建，文件版本与压缩包内程序哈希核对通过；静态组件检查不代表实际窗口布局、鼠标交互或超大文件性能验收。
